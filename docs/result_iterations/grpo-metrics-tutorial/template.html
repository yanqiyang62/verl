刚接触这些词？展开术语速查

Token：模型处理文字的小单元，可能是字、词或词的一部分。

Actor / 策略 π：正在学习的生成模型；π(y) 表示它给下一个 token y 的概率。

Rollout：让生成模型实际采样回答，形成用于训练的轨迹。

Old 策略：这批训练开始前固定下来的策略概率，作为 PPO 更新的比较基准。

Reference：固定参考模型；LoRA 训练中可通过禁用适配器得到参考行为。

ln / nat：自然对数及其信息量单位。概率先取对数，便于相加与比较。

Mask：指定哪些 token 有效，防止 padding 等位置进入统计或损失。

Clip / 裁剪：限制概率比或梯度的大小；PPO 裁剪与梯度裁剪是两种操作。

LoRA：训练一小组附加参数来调整大模型；不是把全部模型参数都更新。

MiB / GiB：分别是 1024² / 1024³ 字节。部分日志键写 MB/GB，页面按实现换算口径标注。

01 / ROLLOUT同一道题生成 2 个回答生成模型按当前权重采样；记录概率和回答。
02 / REWARD与参考答案比较结构与字段匹配获得分数，不执行真实工具。
03 / ADVANTAGE比较同题谁更好减组内均值，再除标准差，得到正负优势。
04 / UPDATE更新 LoRA 并同步提高好回答的概率，加 KL 约束，再同步给采样端。

绝对得分 ≠ 相对学习信号

Reward 回答「这条输出拿几分」，Advantage 回答「它比同一道题的另一个输出好多少」。GRPO 用后者驱动策略学习。

  • 两条都得 0：同分，优势都为 0。
  • 两条都得 1：仍然同分，优势也都为 0。
  • 一条 0、一条 1：优势约为 −0.707、+0.707。本实现使用样本标准差。
  • 优势在每个有效回答 token 上重复；较长回答会影响 token 加权均值。

零优势只表示这组数据没有相对策略信号；KL 正则仍可产生梯度。需要结合梯度和实际权重更新看。

先确认这张图在对谁做统计

  • 训练图横轴：训练 step。一个点是该步日志中的数值，不是单个 token。
  • 系统图横轴：UTC 时间。系统独立采样，采样序号 100 不代表训练 step 100。
  • mean / min / max：通常是同一 step 内的统计。奖励按回答，优势按有效响应 token，负载按分区。
  • 缺失：没有上报与数值为 0 不同。checkpoint 只在部分步记录；稀疏点图不补零。
  • 原始值：保留零值、尖峰和波动。鼠标悬停、触摸或聚焦图表后按方向键，查看每个点。
  • 5 点平滑：当前点与前 4 个有效记录求平均，仅辅助看趋势；tooltip 与统计仍展示原始值。
  • 纵轴：每张图单独缩放，因此两个图的相似形状不代表数值大小相近。可勾选「纵轴含零」检查波动尺度。
  • 快照：本页不自动更新；抓取期间实验仍在运行，不同指标的末尾时间可能略有差别。
V1 训练器还可能跨内部采样迭代聚合：均值按样本数加权、极值取极值、计时求和。不要将整张曲线的历史平均与某个 step 内的均值混为一谈。

KL 是差异度量，关键是「谁与谁比」

图表比较对象主要回答
actor/kl_loss训练中的策略 ↔ 固定参考策略是否偏离初始/参考行为太远？用于本次总损失约束。
actor/ppo_kl当前训练策略 ↔ 此批更新前的 old 策略一次 PPO 更新改动了多少？
rollout_corr/kl
rollout_corr/k3_kl		采样策略 ↔ 训练端重算的 old 策略生成与训练是否一致？可能涉及版本、数值精度或引擎差异。

本次 use_kl_loss=true、kl_loss_coef=0.001，use_kl_in_reward=false。也就是说：KL 在 loss 中起作用，score 与 rewards 不因 reward KL 而分离。直接 KL 是有限样本估计，可出现负值；K3 使用 r − ln r − 1 形式，逐点理论上非负。

这页教程针对这一次配置

  • train_batch_size=1，rollout.n=2：每步少量样本，reward 抖动很大是可能的。
  • shuffle=false，total_epochs=1：不同步的题目并非相同分布；一段均值变好不能独立证明模型改善。
  • ppo_epochs=1，学习率 3e−6，LoRA rank=32 / alpha=64。
  • max_prompt_length=8192；max_response_length=4096；自定义 fixed-prefix agent。
  • 奖励 = 0.8 × 字段匹配分 + 0.2 × 完全匹配；解析与工具契约失败可为 0。它衡量参考一致性。
  • 没有实际调用业务 API，不把 reward 当独立验证的任务成功率。
  • test_freq=−1、val_before_train=false：配置没有周期性或训练前验证；结束时是否验证需看最终日志，本快照没有验证曲线。
  • 配置采用同步 trainer；rollout.mode=async 是生成接口模式，不等同于训练器采用异步过期样本训练。
定义依据是抓取时读取的本地 verl 源码和已安装 SwanLab SDK。运行元信息未提供 Git commit，无法证明正在运行的代码与当前文件逐字相同；每项附有已读取源码片段，方便你复核。仅这份快照不能给出「已经收敛」的结论。

02 / 用一组图回答一个问题

不为单条曲线设万能阈值。

Reward 经常为零，模型没学吗？

先看组内 max/min 是否相同，再看 advantages 的两端与 grad_norm。最后检查生成文本，区分格式失败、字段不匹配和同分。

策略变了，还是采样对不上？

先分清三类 KL；再看概率绝对差、相关系数与样本版本滞后。高相关不保证概率相等。

为什么每隔一段时间变慢？

对照 checkpoint、生成与更新耗时，再核对 token 总量。第 20、40、60 步附近的峰值可先排查保存成本。
